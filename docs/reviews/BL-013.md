## Acceptance evidence

| Requirement | Evidence |
| --- | --- |
| Durable Kafka transport | Real Kafka native 4.2.2, producer acknowledgement trước outbox ack |
| Banking end-to-end | Public transfer HTTP → outbox → Kafka → source + recipient notifications, exact balances |
| Broker outage | Pause/unpause real broker: money stays committed, outbox PENDING, retry delivers after recovery |
| Consumer duplicate/window/restart | DB accept before Kafka offset, duplicate records, close/recreate consumer/group; one inbox/effect |
| Concurrency | 8 concurrent verified accepts → one immutable inbox/notification |
| Poison/conflict/schema | Malformed, changed content and schema v2 → sanitized Kafka DLQ; later valid records progress |
| Durable retry | Notification SQL fault rolls back inbox/effect; immediate retry does not increment attempt, after backoff succeeds |
| Exhaustion | 3 processing failures → broker-acknowledged DLT and durable quarantine, source offset then advances |
| DLT failure | Injected publish failure cannot authorize offset commit or quarantine; retry succeeds, no raw payload copied |
| Ordering | Reverse arrival order of two journals preserves occurredAt order, no overwrite or balance mutation |
| HTTP privacy | Real RSA/JWKS CUSTOMER ownership, 401/403/404, no-store, limit bounds and no identity/PII in response |
| SQL guards | Notification/inbox updates and forged account target are rejected |
| V10 → V11 | Posted money, exact event payload and active outbox lease preserved; notification tables initially empty |
| Default config | Kafka off creates no network clients; ambiguous event/DLQ destination rejected |

## Review limits

[ADR-006](../architecture/ADR-006-kafka-notifications.md), [API](../api/notifications.md),
[local/recovery](../development/local-messaging.md). Kafka + relay default off; enable explicitly for local use.
One logical notification destination, journal aggregate/version1, no global/account ordering, no balance projection.
DLQ contains source coordinates/hash/code, not raw payload; source retention is required for reviewed replay.
No automatic retention pruning, replay endpoint, mark-read, full-history pagination, email/SMS or production cluster policy.
Consumer trusts/verifies the same local outbox, not arbitrary remote journals. Offset identity assumes no topic reset/cluster
incarnation reuse without migration. Owner review policy/commits and decides merge; issue remains under owner control.
