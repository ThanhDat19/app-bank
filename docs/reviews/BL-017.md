## Review invariants

- TransferService has NEVER transaction propagation; replay and posting are separate proxied service calls.
  No remote call can run with a financial transaction/lock. Accounts and balances are validated again under locks.
- Pure unary result is bound to the opaque normalized request ID; unknown/mismatched/late/failed results fail closed.
  Deadline has no success callback that can post money later. Already POSTED replay keeps its original decision.
- Before/after locked posting freshness checks roll back all money/fee/usage/outbox/audit/receipt on expiry/fault.
- V14 risk evidence commits with a new receipt, with SQL hash/POSTED binding, completeness and immutability.
  Legacy inventory preserves original facts without retroactive decisions. SQL guards do not authenticate RPC peers.
- Local-only plaintext simulation, opt-in disabled default, no raw identities/JWT/account IDs forwarded. Approval
  threshold is a principal-only simulated rule and must not be presented as a production fraud/AML policy.
- Separate executable JAR starts no Spring/DB/IAM; shared build is explicit, not an independently released microservice.
